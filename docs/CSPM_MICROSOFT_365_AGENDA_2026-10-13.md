# Microsoft 365 agenda

The owner authorized implementation on October 13, 2026 after discussing the
misleading docket-description matches in Today's queue. The feature replaces
that Professional-home meeting list with a read-only calendar agenda. It does
not create time records, financial transactions, calendar events or deadline
rules. Existing CSPM deadlines remain available through Deadline risk and
Practice Briefing.

## Display and refresh

- Today contains remaining timed appointments, appointments currently underway,
  and all-day events covering today.
- Next 7 days contains tomorrow through seven days ahead, inclusive. The API
  window ends at the following local midnight.
- Event dates and times use America/Toronto, including daylight saving changes.
  Graph returns UTC instants to avoid ambiguous repeated local hours.
- Every returned entry remains reachable in a scrolling list with date, time,
  subject, calendar source and location. Duplicate occurrences shared across
  calendars merge by iCalUId and occurrence start; unrelated meetings sharing a
  title remain separate. Exact matching holiday titles/dates combine sources.
- Network refresh begins after the home window is visible and interactive;
  it never participates in workbook boot or the hidden startup snapshot gate.
  Refresh runs in a separate worker pool, on demand and every five minutes.
- Loading, disconnected, partial failure and stale cached results are labelled.
  Private event data remains in memory; closing the application clears it.

## Calendars and holidays

Graph enumerates `/me/calendars` and reads each enabled calendar's `calendarView`,
including recurring occurrences and exceptions. Owned calendars and readable
shared custom calendars are supported. A shared primary calendar, group calendar,
calendar from another account or calendar stored only in desktop Outlook may
require additional handling; enumeration is not proof that every Outlook-visible
calendar has been discovered. Compare the actual list after first sign-in.

All discovered calendars start enabled and can be individually hidden. Public
supplements are independently selectable:

- Canadian holidays: national and Ontario dates generated by python-holidays.
- U.S. holidays: national dates generated by python-holidays.
- Jewish holidays: Hebcal diaspora dates, including major/minor holidays and
  fast days; daily dates, readings and regular Shabbat entries are excluded.

Actual and observed country-holiday entries retain the publisher's names. This
display is calendar information; it does not assign statutory deadline rules.
Hebcal attribution appears in the source-management dialog. Public queries send
only the year and holiday preferences, never Microsoft tokens or account names.

## Microsoft registration and first connection

1. In Microsoft Entra, create **CSPM Calendar** for **Accounts in this
   organizational directory only**. Leave Redirect URI empty.
2. Copy the **Application (client) ID** and **Directory (tenant) ID**.
3. Under Authentication, enable **Allow public client flows** and save.
4. Add Microsoft Graph **Delegated** permissions **Calendars.Read** and
   **Calendars.Read.Shared**. Grant administrator consent when required by the
   organization's policy. The default User.Read permission can remain.
5. In CSPM's Today's queue, open **Connect calendar**. Enter the two IDs and the
   account's email, save and select **Connect account**.
6. Select **Open Microsoft sign-in**, enter the displayed device code, sign in
   as the configured account and complete Microsoft's consent/MFA screens.
7. Confirm the account and calendar list, then compare Today and Next 7 days
   against Outlook. Hide unwanted calendars or duplicate holiday sources.

No client secret is required. Sign-in checks that the resulting MSAL identity
matches the configured account. Disconnect removes the local sign-in cache;
it does not modify Microsoft calendar events or revoke tenant-wide consent.
Cancelled and declined events are excluded from the agenda.

## Persistence and implementation

Only non-secret connection preferences are stored under `calendarAgenda` in
per-user settings. The user's actual account and registration IDs do not belong
in tracked source. MSAL's token cache uses current-Windows-user DPAPI encryption
with atomic ciphertext-only writes, and has no plaintext fallback. Background
results and sign-in challenges carry revisions so a changed account, cancelled
operation or shutdown cannot accept an earlier result. Calendar workers use a
separate pool from accepted financial saves.

Primary files:

- `services/calendar_auth.py`: sign-in, cancellation and protected token cache.
- `services/calendar_agenda_service.py`: bounded Graph reads, identity, date
  normalization, recurrence handling, filtering, grouping and deduplication.
- `services/holiday_calendar_service.py`: country dates and bounded public
  Hebcal reads with provider attribution.
- `backend/controllers/calendar_agenda_controller.py`: asynchronous QML bridge.
- `components/CalendarAgendaPanel.qml` and `CalendarConnectionDialog.qml`: home
  agenda and account/calendar preferences.

The release lock includes MSAL, tzdata, holidays and their transitive
dependencies. Packaging explicitly includes DPAPI, dynamically imported country
modules and locale/time-zone data. No accepted native motion code changes.

## Validation and remaining acceptance

Focused sandbox-safe checks cover actual QML panel/dialog construction, more than
four reachable entries, startup visibility gating, Toronto DST, recurring and
shared duplicates, date boundaries, all-day spans, cancellation, settings saves,
failure visibility, HTTPS response limits, safe paging and encrypted persistence.
Existing startup briefing and productivity tests remain required.

Real public Hebcal HTTPS reading and synthetic current-user Windows DPAPI
roundtrips are verified separately. Release/startup/WebEngine evidence is recorded
after the exact build. Live Microsoft account sign-in, tenant consent, exact
Outlook calendar coverage and the user's foreground acceptance require their
return. A successful synthetic fixture does not establish those checks.
